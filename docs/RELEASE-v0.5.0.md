# v0.5.0 — 自动锚点生命周期

发布日期：2026-11-01

这次补上最初规划里缺的一块：**锚点会长大，但没有生命周期**。

## 锚点生命周期

- 正文核心上限：`我是谁` 420 字；`你是谁` / `去处` 300 字；`来处` 240 字。
- 超出上限时，按 `卷·日期` 段自动归档：
  - 旧段移到 `锚/历史/<key>/YYYY-MM.md`；
  - 锚点正文保留核心 + 最近段 + `更早的卷：锚/历史/...` 引用；
  - 不删内容、不调模型、不改版本号、可重复执行。
- 写入后自动压缩；维护 tick 也会兜底检查四问。
- 现有「我是谁」已实际压缩：719 → 352 字，3 段归入
  `锚/历史/self/2026-10.md`；完整内容仍在，可从引用回看。

## 修复的缺口

- `anchorChangeAllowed` / `recordAnchorChange` 之前是死代码：现在 `memory_anchor` 写入前会检查
  限额（`self/user/goal` 每日 1 次，`origin` 每周 1 次），成功后记录审计。
- 空锚点不会被编造：夜梦提示词现在明确「有证据才补，没证据保持占位」；
  `你是谁/来处/去处` 仍是占位时，等待真实材料。
- 锚点历史同步思源：`/一页永恒/锚/历史/<label>/YYYY-MM`。
- 保留 0.4.4 的修复：`syncAnchors` 会核对实际 docId，不会再让旧截断文档挡住更新。

## 验证

- 205 项测试通过；`npm run check` 生成一致。
- 实测思源「我是谁」正文约 347 字（核心），历史文档
  `/一页永恒/锚/历史/我是谁/2026-10` 已出现。

## 升级

拉取后重启 DSH；锚点压缩会在下一次写入或维护 tick 自动发生。已有历史文件不会重复归档。
